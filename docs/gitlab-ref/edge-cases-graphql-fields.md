## D. systemNoteIconName (add to A if system-note coverage matters) - H
`SystemNoteHelper.system_note_icon_name` (`app/helpers/system_note_helper.rb:4-64`) vs `system_icon` (R:1519-1545, labelled as that map but invented):

| action | GitLab icon | labrat |
|---|---|---|
| `closed` (MR) | `merge-request-close` | `status_closed` |
| `merge` (MR) / `merged` | `mr-system-note-empty` (action `merge`, MR) / `merge` | `merge` / `merge` |
| `opened` | `work-item-issue` | `status_open` |
| `locked` / `unlocked` | `lock` / `lock-open` (keys are `locked`/`unlocked`) | match arms use `lock`/`unlock`, so real actions `locked`/`unlocked` fall to default `comment` |
| `reviewed` | `comment-lines` | `comment` |
| `cherry_pick` | `cherry-pick-commit` | default `comment` |
| `task` | `todo-done` | default `comment` |
| `reopened`, unknown, `requested_changes` ok | `nil` for unknown actions (null) | default `"comment"` (should be null) |

Query: `notes(filter: ONLY_ACTIVITY){nodes{systemNoteIconName systemNoteMetadata{action}}}` after lock/unlock, review comments, merge. The
labrat `merge` notes created at merge.rs:618-690 therefore report `merge` for the MR note whose GitLab icon is `mr-system-note-empty`.
