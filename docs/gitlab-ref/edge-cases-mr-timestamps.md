# Which operations change a merge request's updated_at / updated_by_id / last_edited_*

Source: GitLab CE 18.11 source (`gitlab-src`), read-only static audit.
Paths are relative to `gitlab-src/`. Confidence: H = read the whole path, M = read the path but a
Rails/gem internal (not in the tree) is assumed, L = inferred.

Legend: `=` unchanged, `bump` = updated_at is written, `set` = value written, `maybe` = conditional (see notes).

## 0. Mechanisms that explain almost everything

| # | Mechanism | Where | Effect |
|---|-----------|-------|--------|
| A | `IssuableBaseService#update` | `app/services/issuable_base_service.rb:337-343` | `updated_by = current_user` (unless only `relative_position` changed), then `save(touch: true)`. Rails writes (and bumps updated_at) only if some column is dirty. Same user as `updated_by_id` and no other dirty column means nothing is written. |
| B | `MergeRequest` includes `ThrottledTouch` | `app/models/merge_request.rb:15`, `app/models/concerns/throttled_touch.rb:9-11` | Every explicit `mr.touch` (and every `touch: true` association callback) is a no-op unless `Time.now - (updated_at_previously_was \|\| updated_at) > 1 minute`. Touch writes only `updated_at`, never `updated_by_id`. |
| C | `Note after_save :touch_noteable` | `app/models/note.rb:211`, `:580-597` (`noteable_object&.touch`) | Any save of a note (user, diff, system, resolve via `save!`) touches the noteable through B. Runs even for `save(touch: false)`. It is an `after_save`, so it does not run on destroy. Skipped when `skip_touch_noteable`, `importing?`, and inside `ApplicationRecord.no_touching` (`Issuable::CommonSystemNotesService`, `app/services/issuable/common_system_notes_service.rb:13`). |
| D | `belongs_to :merge_request, touch: true` | `app/models/merge_request_assignee.rb:6`, `app/models/timelog.rb:23` (the only ones that target MR) | Rails `touch_later`, which at commit calls `touch` on the MR, i.e. goes through B. `touch_deferred_attributes` skips dirty tracking. |
| E | `merge_status` state machine is `timeless` | `app/models/merge_request.rb:294-296`, `lib/gitlab/timeless.rb` | `mark_as_unchecked/checking/mergeable/unmergeable/preparing` save with `record_timestamps=false`: updated_at is NOT bumped. `batch_mark_as_unchecked/checking/clear_error` use `update_all` (`merge_request.rb:~345-385`): no updated_at. |
| F | `state_id` state machine (close/reopen/mark_as_merged/lock) is NOT timeless | `merge_request.rb:~207-250` | `save` -> updated_at bumped, updated_by untouched. |
| G | Webhook `changes` is cumulative per Ruby instance | `app/models/concerns/reportable_changes.rb:28-37`, `app/models/concerns/issuable.rb:592-605`, `lib/gitlab/hook_data/merge_request_builder.rb` safe keys include `updated_at, updated_by_id, last_edited_at, last_edited_by_id` | `changes_applied` is hooked, so every save AND (M) every plain `touch` on the same in-memory MR adds `updated_at` to `changes` as `[value at load, latest]`. `touch_later` (D) clears dirty tracking without `changes_applied`, so it does not show up (M). Hooks fired from a worker build a fresh MR instance, so `changes` there contains only what that worker did. |

## 2. Surprising cases

1. **Updated_at can change with no `updated_by_id` change and no webhook.** Anything that creates a note (comment, system note, async approval note, push note) calls `MR#touch` through `Note after_save` (`note.rb:211,596`). Throttled to once per minute by `ThrottledTouch`. It writes only `updated_at`. There is no MR webhook for plain comments, so a poller sees `updated_at` move silently.
2. **The 1 minute throttle makes label/reviewer/comment edits non-deterministic.** Labels are written via `label_links` and then `issuable.touch` (`labels.rb:21`); a second label change by the same user within 60 s leaves `updated_at` and `updated_by_id` untouched even though labels changed. Reviewer changes have no `touch: true` (assignees do), so the same applies unless the system note passes the throttle. The simulator needs to model `Time.now - updated_at > 60 s` (using `updated_at_previously_was` after a save in the same request).
3. **Resolve via different entry points differs.** `PUT /discussions/:id {resolved}` and GraphQL toggle use `update_all` (no MR touch, note.updated_at set directly); `PUT /notes/:id {resolved}` uses `Note#resolve!` -> `save!` (MR throttled touch). Draft-note publish with `resolve_discussion` takes the discussion (`update_all`) path.
4. **Deleting notes never changes MR timestamps; award emoji (MR or note) never do either** (note gets `update_columns(updated_at)` only).
5. **Title edits never set `last_edited_*`; only description edits (and task-checkbox toggles) do.** Draft/ready is a title edit so `last_edited_*` stay untouched. Task-list toggle is the only path that sets `last_edited_*` without a text change by the user's editor.
6. **`updated_by_id` is set only by `IssuableBaseService#update` (A), `UpdateAssigneesService`, `UpdateReviewersService` and task toggles.** Close, reopen, merge, rebase, auto-merge enable/abort, push-draft (`update(title:)`), time spend via `AddSpentTimeService`, `merge_error` writes: updated_at bumps (or not) but `updated_by_id` stays at whoever last edited. Also, `state_event=close` through `UpdateService` DOES set `updated_by_id` while the direct Close endpoint does not.
7. **Merge status churn never bumps updated_at** (timeless state machine + `update_all` batch variants), and neither do `head_pipeline_id`, `merge_jid`, `rebase_jid`, `merge_ref_sha` (`update_column`). A push alone, in the simulator, should not change `updated_at` of the MR except through the "added N commits" system note (throttled) and, on a source-branch push, the diff-position re-save of diff notes.
8. **Assignee changes always bump updated_at** (explicit `updated_at: Time.current` in `UpdateAssigneesService` + `touch: true` on the join model + explicit `issuable.touch`), so unlike reviewers they don't suffer from the same-user no-op.
9. **Webhook `changes` is cumulative and includes touches.** `ReportableChanges#changes_applied` (`reportable_changes.rb:28`) runs on saves and plain `touch`es of the same Ruby object, so e.g. a label webhook can include `updated_at` while `updated_by_id` is absent, and a synchronous system note touch (unapprove, request review, reviewer change) can add `updated_at` too. Async-built hooks (approve, merge worker) only see what the worker did. The first value in `[previous, current]` is the value at load, not at the last save.
10. **Merge writes updated_at several times** (in-progress sha set and cleared, merge/squash sha `update!`, state transition, merge_params update) but never `updated_by_id`; `merge_user_id` is set only for auto-merge.
11. **`merge_after` alone is a no-op on MR columns** (child row only).
12. **Unverified assumptions (M/L):** Rails internals (touch_later calling the overridden `touch`; `touch` calling `changes_applied`) are not in the tree, so rows that depend on them (D, G) are medium confidence. Verify against a real instance by checking `updated_at` after a time-spend and after an assignee add.
