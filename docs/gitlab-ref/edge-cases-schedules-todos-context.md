# Edge cases: scheduled merges, to-dos, MR context commits

Source review of GitLab 18.11 (CE source copy) against labrat. Paths are relative to the
GitLab source and `/home/mabn/dev/shed/labrat`. Impact: H = common API flow shows a visible difference,
M = observable in a specific sequence, L = cosmetic or rare. "Unverified" means the GitLab behaviour was read but
not confirmed in detail.

## 3. Scheduled merges (`merge_after`)

| # | Impact | GitLab | labrat | Effect / repro |
|---|---|---|---|---|
| S1 | M | `mergeabilityChecks` is `all_mergeability_checks_results` (`merge_request.rb:1714`), executed with `execute_all: true`. | S2 | M | `merge_after` parsing: Grape `String`, then ActiveRecord `datetime` cast (`UpdateMergeScheduleService` assigns it directly). | S4 | L | `UpdateMergeScheduleService` is called before the rest of the update (`update_service.rb:18-21`) and assigning a has_one saves immediately. ## 4. Suggested priority for fixes

1. T1 (resolve only the actor's to-dos on merge/close/push).
2. T2 and T3 (to-do de-duplication; `review_submitted` double for author-assignee).
3. T4 and T5 (description mention to-dos; note edit mentions).
4. R1 and G2 (mark-all-done honouring filters).
5. G1 (GraphQL `targetUrl` / `target` / `note`).
6. C1 (20-commit limit) and C2 (ref names rejected).
7. S1 (all mergeability checks with SUCCESS/INACTIVE) and S2/S3 (time parsing).
8. T6, T7, T8, T9 (thread-scoped resolution, build_failed/unmergeable, emoji, update resolution).
9. R2, R3, R4 (REST filters, access filter, body/target_url).
